# IceForce — kr3-responsive-shop

Учебный многостраничный интернет-магазин хоккейной экипировки, выполненный в рамках дисциплины «Фронтенд и бэкенд разработка».

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

**Автор:** Дончу Артём, группа ЭФБО-03-25

**Опубликованная версия (GitHub Pages):** https://donch27.github.io/kr3-responsive-shop/

## Описание проекта

Проект основан на HTML/CSS-сайте из КР №1 ([kr1-html-css-shop](https://donch27.github.io/kr1-html-css-shop/)). Первый коммит репозитория — перенос КР №1 без изменений, дальнейшие коммиты — адаптация и доступность. Bootstrap и другие CSS-фреймворки не используются: сетки построены на CSS Grid и Flexbox, адаптивность — на собственных медиазапросах.

Сайт IceForce — каталог хоккейной экипировки: главная страница с популярными товарами и каруселями категорий, каталог с фильтрами, страница товара с таблицей характеристик, форма заявки, контакты, а также страницы «Доставка и оплата» и «Подбор экипировки» из КР №1.

## Структура проекта

```text
kr3-responsive-shop/
├── index.html          — главная: hero, преимущества, популярные товары, категории, окно быстрого заказа
├── catalog.html        — каталог: фильтры по категории и цене, сортировка, сетка карточек
├── product.html        — страница товара: фото, описание, таблица характеристик (product.html?id=...)
├── order.html          — форма заявки со сводкой заказа (order.html?product=...)
├── contacts.html       — контакты и форма обратной связи
├── delivery.html       — доставка и оплата (из КР №1)
├── size-guide.html     — подбор размерной категории (из КР №1)
├── css/
│   ├── style.css       — базовые (мобильные) стили
│   └── responsive.css  — медиазапросы min-width для планшета и desktop
├── js/
│   └── main.js         — меню, модальное окно, проверка форм, фильтры, страница товара
```

На каждой странице подключены `css/style.css`, затем `css/responsive.css` (чтобы адаптивные правила переопределяли базовые) и есть `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.

## Адаптивные решения

- Добавлен отдельный файл `css/responsive.css`, подключён после `style.css` на всех страницах.
- Применён подход **Mobile First**: в `style.css` описана мобильная версия без медиазапросов, в `responsive.css` — только `@media (min-width: …)`.
- Контрольные точки: **480px** (крупные телефоны), **768px** (планшет), **1024px** (desktop), **1440px** (широкий desktop).
- **Навигация:** на мобильном и планшете — кнопка «Меню» с выпадающим списком, с 1024px — строка ссылок. Шапка закреплена (`position: sticky`), для якорей задан `scroll-padding-top`, чтобы шапка не перекрывала заголовки.
- **Hero-блок:** высота, размер заголовка и отступы растут с шириной экрана; кнопки на мобильном стоят столбцом, с 480px — в строку. Фон — `<picture>` с `object-fit: cover`.
- **Сетка карточек (CSS Grid):** 1 колонка → 2 колонки (480px) → 3 колонки. На главной с 480 до 767px карточка «Хит» занимает всю строку (`grid-column: 1 / -1`), две другие стоят рядом.
- **Карточки (Flexbox):** кнопки «Подробнее» и «Заказать» переносятся (`flex-wrap`) и не слипаются; цена и кнопки прижаты к низу, поэтому карточки в ряду одной высоты.
- **Каталог и боковой фильтр:** на мобильном фильтр сворачивается в кнопку «Показать фильтры», с 1024px — закреплённая боковая колонка (`grid-template-columns: 260px 1fr`, `position: sticky`). С 1440px товары идут в 3 колонки.
- **Страница товара:** на мобильном фото над описанием, с 768px — фото и описание рядом.
- **Таблица характеристик:**
  - до 480px — карточное представление: каждая строка таблицы — отдельная карточка, подписи берутся из `data-label`;
  - 480–767px — обычная таблица в `.table-wrapper` с собственной горизонтальной прокруткой (`min-width: 560px`), страница при этом не прокручивается вбок;
  - с 768px — таблица на всю ширину.
- **Формы:** на мобильном одна колонка, с 768px — две колонки (`grid-template-columns: repeat(2, 1fr)`), длинные поля занимают всю строку. Поля высотой не меньше 44px, шрифт полей 16px (iOS не увеличивает страницу при фокусе), кнопки на мобильном на всю ширину. На странице заявки с 1024px сводка заказа стоит справа и закреплена.
- **Модальное окно:** ширина `calc(100% - 16px)` с максимумом 600px, максимальная высота `100dvh` с внутренней прокруткой; форма внутри тоже перестраивается в 2 колонки.
- **Горизонтальный скролл:** исключён на всех ширинах. Горизонтальная прокрутка есть только внутри каруселей категорий и `.table-wrapper`. Для длинных слов задан `overflow-wrap: break-word`, у вложенных grid/flex-элементов — `min-width: 0`.
- **Адаптивные изображения:**
  - базовое правило `img, video, picture { max-width: 100%; height: auto; }`;
  - все товары выводятся через `<picture>`: AVIF → WebP → JPG, каждый формат в двух размерах (400w и 800w) через `srcset`, а `sizes` описывает ширину картинки в сетке на каждой контрольной точке;
  - фон hero-блока — `<picture>` с вариантами 480w и 740w;
  - у всех изображений есть `width`/`height` (нет скачков вёрстки при загрузке), картинки ниже первого экрана грузятся лениво (`loading="lazy"`).
- `prefers-reduced-motion`: при настройке «меньше анимации» отключаются переходы и плавная прокрутка.

## Доступность

- Добавлена **ссылка пропуска** «Перейти к основному содержимому» — первый элемент при навигации с клавиатуры.
- **Видимый фокус** на всех интерактивных элементах (`:focus-visible`, рамка 3px). На тёмных блоках (шапка, подвал, hero) цвет рамки — золотой, на светлых — тёмно-зелёный.
- **Одна `h1` на каждой странице**, заголовки идут по порядку (h1 → h2 → h3 без пропусков). На страницах доставки и подбора экипировки исправлены заголовки карточек (были `h2` внутри секции с `h2`, стали `h3`).
- **Семантика:** `header`, `nav` (основная навигация, хлебные крошки, навигация в подвале — с разными `aria-label`), `main`, `section`/`article`/`aside`, `footer`. Хлебные крошки — список `ol` с `aria-current="page"`, активный пункт меню тоже отмечен `aria-current="page"`.
- **Формы:**
  - у каждого поля есть `label`, связанные поля сгруппированы в `fieldset`/`legend`, у полей стоит `autocomplete`;
  - при ошибке сообщение выводится текстом под полем и связано с ним через `aria-describedby`, поле получает `aria-invalid="true"`, а фокус переходит на первое поле с ошибкой;
  - результат отправки объявляется через `role="status"`.
- **`alt` у изображений:** у товаров — описание того, что изображено; декоративные картинки (фон hero, картинки внутри карточек-ссылок с текстом) — `alt=""`.
- **Ссылки и кнопки по назначению:** переходы — `<a>`, действия — `<button>`. У повторяющихся «Подробнее» и «Заказать» есть скрытое уточнение, например «Подробнее о товаре "Хоккейный шлем"».
- **Контраст:** кнопки и текст проверены на соотношение не меньше 4,5:1. Исправлены цвета из КР №1: белый текст на зелёном бейдже «Новинка» и уведомлении (было около 3,3:1), приглушённый серый текст.
- **Модальное окно** (`<dialog>` + `showModal()`):
  - фокус удерживается внутри окна и при открытии ставится на первое поле;
  - окно закрывается по Esc, кнопке «×», «Отмена» и клику по фону;
  - после закрытия фокус возвращается на кнопку, которая открыла окно;
  - заголовок связан через `aria-labelledby`, прокрутка страницы под окном заблокирована.
- **Мобильное меню:** кнопка с `aria-expanded` и `aria-controls`, Esc закрывает меню и возвращает фокус на кнопку. Без JavaScript меню просто показано списком.
- **Карусели категорий:** прокручиваемая область доступна с клавиатуры (`tabindex="0"`, `role="region"`, `aria-label`). Колесо мыши больше не «застревает» на карусели — у края прокрутка передаётся странице.
- Размер всех кликабельных зон — не меньше 24×24px, основные кнопки и поля — 44px.
- ARIA используется только там, где нет подходящего HTML-элемента.

## Lighthouse

Проверка выполнена в Chrome DevTools → Lighthouse, категория **Accessibility**, страницы `index.html`, `catalog.html`, `order.html`.

Отчёты сохранены в папке `lighthouse/`:

```text
lighthouse/
├── accessibility-report.png    — сводный скриншот
├── accessibility-index.png
├── accessibility-catalog.png
└── accessibility-order.png
```

Перед проверкой Lighthouse выполнена ручная и автоматическая проверка тех же правил (контраст текста, `label` у полей, `alt` у изображений, имена кнопок и ссылок, порядок заголовков, ссылки ARIA на существующие `id`, размер кликабельных зон) на ширинах 360 и 1440px — замечаний нет. Lighthouse не заменяет ручную проверку: навигация с клавиатуры (Tab, Esc, работа модального окна) проверена вручную.

## Проверенные ширины

| Ширина | Устройство | Что меняется |
|---|---|---|
| 360px | мобильный | меню-кнопка, 1 колонка карточек, таблица карточками, форма в 1 колонку |
| 430px | крупный мобильный | то же, что 360px |
| 768px | планшет | 2–3 колонки карточек, форма в 2 колонки, товар: фото и описание рядом, подвал в 3 колонки |
| 1024px | небольшой desktop | меню в строку, боковой фильтр каталога, сводка заказа справа |
| 1440px | широкий desktop | каталог в 3 колонки, увеличенный hero |

На каждой ширине проверены шапка, навигация, hero, сетка карточек, каталог и фильтр, страница товара и таблица, форма заявки, контакты, подвал и модальное окно. Горизонтального скролла страницы нет ни на одной ширине.

## Самостоятельные доработки

- **Мобильное меню** с анимированной иконкой, `aria-expanded`, закрытием по Esc, клику вне меню и переходу на desktop.
- **Рабочие фильтры каталога:**
  - фильтрация по категориям и цене без перезагрузки;
  - сортировка по цене и названию;
  - счётчик найденных товаров, объявляемый скринридеру;
  - сообщение «ничего не найдено» с кнопкой сброса;
  - фильтры сохраняются в адресе страницы, например `catalog.html?category=protection&sort=price-asc`, — такой ссылкой можно поделиться.
- **Таблица характеристик в трёх вариантах:** карточки, прокрутка в `.table-wrapper`, полная таблица.
- **Три формата изображений** (AVIF, WebP, JPG) в двух размерах через `<picture>`. AVIF весит примерно в 3 раза меньше JPG. Исправлены файлы из КР №1, у которых внутри `.jpg` на самом деле были WebP и AVIF (а у шлема — WebP с прозрачностью).
- **Страница товара для всех 12 товаров** по адресу `product.html?id=...` со своими характеристиками и блоком «С этим товаром выбирают».
- **Форма заявки:**
  - подставляет товар из адреса (`order.html?product=skates`);
  - отключает размеры, которых нет у выбранного товара;
  - считает итоговую сумму;
  - показывает поле адреса только для курьерской доставки;
  - не даёт выбрать дату в прошлом.
- **Доступная проверка форм** с текстом ошибки под полем вместо всплывающих подсказок браузера. Без JavaScript работает стандартная проверка браузера.
- **Исправлены ошибки КР №1:**
  - удалено подключение несуществующего `js/category-slider.js`;
  - выровнено меню на всех страницах (на двух страницах было 5 пунктов вместо 8 и не подсвечивался активный);
  - цены на главной и в каталоге приведены к одним значениям;
  - уведомление о заказе в каталоге теперь исчезает;
  - форма обратной связи обрабатывается;
  - стили страниц «Доставка» и «Подбор экипировки» перенесены из `<style>` в общий CSS;
  - удалены дублирующиеся и неиспользуемые правила.
